# Direct playback resume header

Device evidence on .118, 2026-11-27: HA showed Dexter: Wiedererwachen S2E2 playback from 20:14 to 20:17. CloudStream native store contained parent 1447063914, episode 1447263917, position 175801 ms, duration 3574720 ms, but no matching download_header_cache record. The older Moflix header has a different parent ID and is not a valid replacement. Upstream HomeViewModel.getResumeWatching() skips resume pointers if both native header and backup are absent. ResultViewModel2.load() normally writes the header; ILauncherDirectPlay bypasses it.

Before actual direct player navigation (automatic and selected provider), persist the exact selected generator page's native DownloadHeaderCached under the selected episode's parent key, validating response.getId() matches. Remember provider-supplied series identity through the existing helper. Do not write progress, resume pointer, watched flags or Android rows from the new helper. Keep normal native publication and playback behavior. Never log URLs. On storage failure log exception type and allow playback.

Three JVM tests cover native parent matching and full header, opaque provider references for films without artwork, and invalid input rejection. Already orphaned resume entries can become visible once the same provider's parent header is recreated; do not infer missing provider URL from an unrelated cached title.
